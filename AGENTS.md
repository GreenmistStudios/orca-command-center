# AGENTS.md

Guidance for coding agents working in this repository. Read [README.md](README.md) for what the
product does and [Plan.md](Plan.md) for architecture, derivation rules, API and budgets.

## Project shape

- `src/server/`: Node 22 HTTP + SSE server (`node:sqlite`, read-only). Sources normalize into
  `src/shared/` contract types; the store derives state, attention and stats.
- `src/client/`: React 19 SPA (Vite, zustand, React Flow + ELK, Tailwind v4). `src/client/api/mock.ts`
  is a seeded in-browser backend used by `?mock=1`.
- `bin/occ.mjs`: CLI entry; serves `dist/client`. Run `npm run build` before `npm start` or e2e.
- `test/`: `integration/` and `fixtures/` (vitest, node), `client/` (vitest, jsdom),
  `e2e/` (Playwright).

## Commands

```bash
npm install
npm run typecheck       # server, client and test tsconfigs
npm test                # vitest: unit + integration (server and client projects)
npm run build           # client (vite) + server (tsc)
npm run e2e             # Playwright smoke: real + mock projects (installed Chrome)
npm run test:visual     # Playwright pixel screenshots against the mock backend
npm run test:live       # Playwright integration against this machine's live data
```

Before finishing a change, run `npm run typecheck` and `npm test`. If you touched UI, also run
`npm run build && npm run test:visual`.

## Screenshot tests

- `test/e2e/visual.spec.ts` captures core surfaces (fleet, each view with a session selected,
  palette, shortcuts, oversight board, status bubble, degraded sources, light theme) using `?mock=1`.
- Determinism depends on the fake clock: the clock is installed and paused at a fixed instant
  *before* navigation, and fake time advances only through `page.clock.runFor`, after the UI has
  bootstrapped. Keep this order when adding tests, or the mock's live ticks drift between runs.
- Baselines live in `test/e2e/__screenshots__/<platform>/`. Update the macOS ones with
  `npm run test:visual -- --update-snapshots`. Linux (CI) baselines are generated by running the
  CI workflow manually with `update-snapshots=true` and committing its artifact.
- An intentional UI change means updating baselines in the same commit; review the diff images in
  `test-results/` first.
- `test/e2e/live.spec.ts` runs against real local data: it checks that the UI agrees with the API
  and saves screenshots to `test-results/live/` without comparing pixels. It skips when there are
  no sessions, so it does not run in CI.
- `test/e2e/live-copilot.spec.ts` (also `npm run test:live`) covers Orca running with Copilot CLI
  as the harness: Orca pill shows the API's pid, the Copilot harness filter shows exactly the
  API's Copilot root sessions, and the inspector loads one. It skips unless Orca is running and a
  Copilot root session exists. Screenshots go to `test-results/live-copilot/`.

## Rules

- **Read-only is a product guarantee.** Never add writes to agent databases, Orca, or the
  filesystem outside the app; the HTTP API is `GET`/`HEAD` only; the Orca CLI allowlist is fixed.
  `npm run audit` checks this.
- Never read credential files (see "Never read" in the README and `docs/data-sources.md`). Route
  every transcript-derived string through redaction.
- Keep the mock backend (`src/client/api/mock.ts`, `mock-data.ts`) seeded and deterministic.
  Changing its data changes visual baselines.
- Use the existing `data-testid` attributes for selectors; add new ones instead of relying on text
  or CSS classes.
- Commits follow `type: summary` (conventional commits), matching `git log`.
